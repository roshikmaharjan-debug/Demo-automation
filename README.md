# Playwright Demo Automation

End-to-end browser tests for the [Sauce Demo](https://www.saucedemo.com/)
application, written with Playwright Test and TypeScript. The project uses
feature-based test files and page objects (POMs) to keep test scenarios and
page interactions organized.

## Prerequisites

- Node.js LTS
- npm

## Install

Install dependencies from the lockfile:

```bash
npm ci
```

Install the Chromium browser used by the Playwright configuration:

```bash
npx playwright install chromium
```

## Run tests

Run every test:

```bash
npm test
```

Run a particular test file:

```bash
npx playwright test tests/login.spec.ts
```

Run tests in headed mode:

```bash
npx playwright test --headed
```

Open Playwright's interactive UI:

```bash
npx playwright test --ui
```

Open the HTML report generated by a test run:

```bash
npx playwright show-report
```

### Page objects

- `login.page.ts` — opens the login page and submits credentials.
- `inventory.page.ts` — selects products, sorts prices, and navigates to the cart.
- `cart-checkout.page.ts` — completes the checkout flow.
- `side-menu.page.ts` — handles logout, the dynamic catalog spinner, and About navigation.

### Test files

- `login.spec.ts` — successful login, incorrect password, and locked-out user.
- `inventory.spec.ts` — inventory count, price sorting, and product details.
- `cart-checkout.spec.ts` — adding products and completing an order.
- `navigation.spec.ts` — logout, About page, and dynamic catalog spinner.
- `problem-user.spec.ts` — product image, cart, and checkout behavior for `problem_user`.
- `performance-glitch.spec.ts` — cart behavior for `performance_glitch_user`.
- `login-audit.spec.ts` — login audit persistence against the local SQLite database.
- `api/booking.spec.ts` — Restful Booker booking lifecycle and update-without-token tests. See [docs/api-layers.md](./docs/api-layers.md).

Playwright runs the `setup` project before Chromium tests. The
`tests/auth.setup.ts` setup test signs in as `standard_user` and saves the
browser storage state under `playwright/.auth/`.

## Example: page object and test

The page object contains reusable page interactions:

```ts
// tests/pages/login.page.ts
import { Locator, Page } from "@playwright/test";

class LoginPage {
  page: Page;
  username: Locator;
  password: Locator;
  loginButton: Locator;

  constructor(page: Page) {
    this.page = page;
    this.username = page.getByPlaceholder("Username");
    this.password = page.getByPlaceholder("Password");
    this.loginButton = page.getByRole("button", { name: "Login" });
  }

  async goto() {
    await this.page.goto("/");
  }

  async login(username: string, password: string) {
    await this.username.fill(username);
    await this.password.fill(password);
    await this.loginButton.click();
  }
}

export default LoginPage;
```

A test creates the page object with Playwright's `page` fixture, then asserts
the expected result:

```ts
// tests/login.spec.ts
import { expect, test } from "@playwright/test";
import LoginPage from "./pages/login.page";

test("logs in successfully", async ({ page }) => {
  const loginPage = new LoginPage(page);
  await loginPage.goto();
  await loginPage.login("standard_user", "secret_sauce");

  await expect(page).toHaveURL("https://www.saucedemo.com/inventory.html");
});
```

The configured `baseURL` is `https://www.saucedemo.com/`, so `page.goto("/")`
resolves to the Sauce Demo home page.

## Fixtures

The shared custom fixtures in `tests/fixtures/fixtures.ts` provide one
`pomManager` per authenticated UI test; it is built with `loggedInPage`, which
navigates to the inventory using the saved authentication state. Tests that
start signed out should create only the page objects they need with Playwright's
`page`. The same fixtures provide the database and API managers. Authentication
state is prepared by the Playwright setup project.

## Database-backed tests

The login audit test uses a local SQLite database. Playwright's global setup
initializes its schema and test accounts before each test run; no database
server is required. See [docs/db-layers.md](./docs/db-layers.md) for the
layer-by-layer design.

Run `npm run seed` to initialize or refresh the local SQLite schema and sample
users without running the browser tests.

## API tests

The API tests run against [Restful Booker](https://restful-booker.herokuapp.com)
in the `api` Playwright project (no browser). Copy `.env.example` to `.env`
before running them locally:

```bash
npx playwright test --project=api
```

In CI, set the repository variable `API_BASE_URL` and the secrets
`API_USERNAME` and `API_PASSWORD`. See
[docs/api-layers.md](./docs/api-layers.md) for the layer-by-layer design.

## Credentials

The examples use Sauce Demo's public test account
(`standard_user` / `secret_sauce`). Do not put private credentials in test
source files; use environment variables and CI secrets for non-public accounts.

## Continuous integration

The GitHub Actions workflow installs dependencies and Playwright browsers,
runs the test suite on pushes and pull requests targeting `main` or `master`,
and uploads the HTML report as an artifact.
